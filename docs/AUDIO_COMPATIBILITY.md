# 默认音频输出兼容性

## 0.7.0 当前实现

本轮用户要求完成全部扩展功能，新增直接输出切换，替代 B4b 的纯设置入口策略。AudioSwitchCapability.Available 现在表示兼容适配器已实现，不表示具体硬件组合已验证。

CoreAudioService 的独立 partial 适配封装 Windows PolicyConfig 兼容接口。该接口并非承诺稳定的公开 API，失败时报告并提供系统设置入口。只修改 Console/Multimedia，Communications 保留。先确认目标为活动输出，逐角色写入并读回；恢复时仅恢复仍等于本次目标的角色，避免覆盖外部变化。

麦克风操作显式读取的默认输入 ID；写入前确认默认输入未变化，操作后读取静音值。硬件断开或接口不可读时显示失败。假实现流程已验收，真实 OS/驱动/设备组合尚未验收。本次开发没有操作用户真实音频。

接口布局参考：[EarTrumpet 的 PolicyConfig 声明](https://github.com/File-New-Project/EarTrumpet/blob/master/EarTrumpet/Interop/MMDeviceAPI/IPolicyConfig.cs)。本项目独立封装适配与恢复逻辑，没有引入整个第三方项目。

## B4b 历史记录（不代表新版实现状态）

2026-09-26。结论：**原生默认输出切换禁用，保留系统声音设置入口；音量/静音独立可用。**

当前 AudioSwitchCapability 为只读能力门，没有已验证环境白名单；配置、导入的未知字段和设置控件均不能开启此能力。本版没有连接用于切默认端点的未验证 COM 写接口，不把“枚举成功”当成“切换兼容”。

只读快照分别查询 Console、Multimedia、Communications 三角色，设备列表分别显示角色标签，不假设三者一致。不记录真实端点 ID 到导出配置。

| 环境 | 默认设备枚举/逐角色查询 | 原生切换/逐角色回读/部分失败 | 能力 |
|---|---|---|---|
| 假服务自动测试 | 不同角色展示通过 | 未执行实际原生切换 | 禁用 |
| 当前用户 Windows 11 环境 | B4 新增 Console 查询未实测 | 未执行，用户游戏期间禁止 | 禁用 |
| Windows 11 稳定版其他机器 | 未执行 | 未执行 | 禁用 |
| Insider/其他系统构建 | 未执行 | 未执行 | 禁用 |

启用前必须在声明支持的具体 OS build/驱动/设备组合中验证：普通权限、多角色目标一致性、外部切换、设备拔出、睡眠恢复、部分失败、每角色真实回读；记录原值、目标、实际结果和外部变更。若部分角色失败，明确报告部分成功，不无条件回滚覆盖用户或其他程序刚改的值。

未满足门槛保持降级，不能称为原生切换已实现或已通过。B4b 本轮完成能力门、三角色查询代码与支持矩阵；兼容真机验收仍待安排，不因此修改用户机器音频设置。
