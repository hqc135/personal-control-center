# 个人控制中心：开发提示词包

配套文档：`PERSONAL_CONTROL_CENTER_DEVELOPMENT.md`（2026-09-11，v1.0）。

用途：把开发规格交给编程 AI 实现。本文件只是可复制的任务文本，不代表已经授权当前会话开始安装或开发。

## 使用方法

把开发文档和本文件放在新项目可读取的位置，发送下面的「主提示词」。如果只想先看效果，改用「仅做 M0–M1」。同一任务后续使用「继续开发」；已有代码后使用「独立验收」。无需一次发送所有提示词。

建议独立项目目录，不要直接把 Windows 考古目录当应用源码目录。主提示词默认使用当前工作目录下的 `PersonalControlCenter` 子目录；已有项目则原地继续，不覆盖现有工作。

## 1. 主提示词：完整实现

复制以下整段，并同时附上开发文档：

```text
请依据附件 PERSONAL_CONTROL_CENTER_DEVELOPMENT.md，实现一个真实可运行的 Windows 11 个人控制中心。不是再写方案，也不是网页原型：我要 C# / .NET 10 LTS / WPF 的原生托盘应用，以及可复现的源码、测试和发布包。

先完整阅读开发文档和项目中的适用开发约定，再检查当前目录、已有代码、Git 状态和 SDK。若文档缺失，先让我提供，不要猜测内容。默认在当前目录的 PersonalControlCenter 子目录建立项目；若已存在对应源码，先检查并继续，不重建、不覆盖用户修改。不要把考古报告、个人配置或调优脚本打包进去。

产品与审美：
- 这是我自己的轻量桌面工具，喜欢 macOS 式的克制、清晰层次和苹方字体，不需要照抄苹果界面。
- 主界面必须是实际 WPF 窗口，不引入 Electron、WebView、本地网站或云服务。
- 先把字体、间距、图标、状态反馈和键盘操作做好，再加可随时打断的短过渡。不要大幅缩放文字、拖沓弹跳、不断播放的装饰动画。
- 实色背景是基线。材质或动画如果割裂、掉帧，就默认关闭，不能为了视觉效果牺牲交互。
- 使用本机已有字体并提供回退，不分发苹方字体文件。

功能范围严格按文档：音量与静音、音频输出、电源方案、临时保持唤醒、本机代理状态和手动连接测试、常用入口、托盘、设置与可选快捷键。不要顺手加入 AI、天气、新闻、插件市场、监控曲线或系统清理。

实现纪律：
1. 按 M0–M5 推进。先把 SDK、托盘和原生 API 可行性摸清，再搭界面并逐项接入。每阶段构建和测试；阶段完成后继续下一项安全可执行工作，不必每阶段等我回复。
2. 保持 App / Core / Windows 的依赖边界，Core 不引用 WPF 或原生 API。接口草图可以修正为可编译代码，但重大设计变更必须记录理由。
3. 系统状态必须真实读取。pending、过期、失败、部分成功分开表达，不能按钮一亮就声称操作成功。
4. 默认音频设备切换是兼容性风险，不把非公开接口说成受支持公共 API。未通过测试时，禁用该能力并打开系统声音设置；保留已验证的音量与静音功能。
5. 保持唤醒必须由固定长期存活线程设置和清除，退出释放。代理端口可达不等于互联网正常。配置导入不得自动执行程序入口。
6. 默认单元测试使用假服务，不能改变宿主音量、电源或网络。mock 模式显著标记“演示数据”，发布默认真实模式，不能用假状态补缺失能力。
7. 遇到编译和测试失败，定位根因并修复；不要删测试、降低断言或吞异常来制造成功。
8. 不虚构测试结果。没有相应显示器、刷新率、系统版本或交互能力的测试写“未验证”，而不是通过。性能预算也必须测量，不能推断达标。

权限与主机保护：
- 允许在项目内创建源码、文档和构建产物，恢复项目依赖，执行非破坏性构建与假服务测试。
- 缺少 SDK 或需要机器级安装时，先报告所需版本、用途和影响，等待批准；不要静默安装、提权或修改全局环境。
- 编写控制系统的功能不等于授权你在我的电脑上自动执行它们。首次真机写入音量、切换默认设备、电源方案、保持唤醒，以及重启 Explorer 等测试，必须列出准确操作和恢复方式，得到批准后执行。
- 不修改 Windows Update、服务、注册表调优、电源参数、浏览器、VS Code、Docker/WSL 或代理配置；不读取密码、订阅密钥、浏览器个人数据。
- 不自动开机自启、不启动 Clash、不占用未经选择的全局快捷键、不发起后台外网探测。实现自启设置可以，但测试写入需要明确批准。
- 不覆盖已有用户文件，不做破坏性 Git 操作，不自动提交、推送或公开发布。便携 ZIP 是本地交付，不等于联网发布。

在项目中持续维护：
- docs/IMPLEMENTATION_STATUS.md：M0–M5 状态、完成证据、当前阻塞和下一步。
- docs/DECISIONS.md：重要选择、偏离规格的原因与影响。
- docs/TEST_RESULTS.md：自动测试命令与实际结果；真机测试编号、环境、结果和证据。明确区分通过/失败/未验证/不适用。
- docs/MANUAL_CHECKLIST.md：需要我执行或授权的事项，写明原因、步骤、预期、恢复方式。

最终交付：可编译源码、固定 SDK 与依赖锁文件、Release 自包含 win-x64 ZIP、SHA256、README、配置示例、许可证和第三方声明、测试结果与已知限制。不要替我虚构版权所有者或任意决定尚未确认的项目开源许可证；可先声明待确认，第三方许可证必须准确。

首先给出简短的环境检查结果和执行顺序，然后直接开工。缺少非关键偏好时使用文档安全默认值；遇到真正需要新授权的事项先隔离，继续其余工作。无法继续时明确说明阻塞，不把候选构建说成已完成正式验收。
```

## 2. 仅做 M0–M1：先验证原生窗口手感

适合先决定值不值得继续投入。与主提示词二选一发送。

```text
请完整阅读随附 PERSONAL_CONTROL_CENTER_DEVELOPMENT.md，这一轮只实现 M0–M1，不进入后续系统控制开发。

在独立 PersonalControlCenter 项目中建立 C#/.NET 10/WPF 骨架，完成普通权限启动、单实例、托盘、面板、主题和键盘操作，五个模块使用明确标注的演示数据。原生可行性检查优先只读；没有授权不要实际改音量、切电源、保持唤醒或重启 Explorer。

界面遵循文档的 360 DIP 面板、字体回退、统一矢量图标和实色背景基线；开合可中断，尊重系统动画设置。不要以 WebView 或截图代替真正的 WPF UI。不要为展示效果添加无关功能。

先检查 SDK，缺少需要安装的依赖时报告并等待批准，不修改全局环境。项目依赖恢复与非破坏性构建测试可以直接执行。保留现有文件，不修改我的系统调优。

交付可运行的 M1 演示 ZIP、源码、构建与测试记录、API 可行性风险和下一阶段清单。明确哪些 UI/DPI/动效已实测，哪些需要我体验；M1 交付后停止，不自动扩展到 M2。
```

## 3. 继续开发：避免换会话后重做

```text
请继续当前 PersonalControlCenter 项目。先阅读开发规格、docs/IMPLEMENTATION_STATUS.md、docs/DECISIONS.md、docs/TEST_RESULTS.md 和适用项目约定，再检查实际源码与 Git 状态。

不要把进度文档当作验证证据：用现有测试和代码核实当前状态，但不要重复已经完成的设计或推倒重来。找出第一个未完成且安全可执行的里程碑，从那里继续，保持原有权限边界和真实系统状态要求。

本次只延续已授权的开发范围，不把历史上“可以管理员运行”等模糊表述当作新的真机修改批准。将需要人工操作的测试留入清单，继续不受阻的实现。结束时更新状态、实际测试结果、候选包及下一步，清楚区分代码完成和真机验收完成。
```

## 4. 独立验收：检查是不是能放心常驻

```text
请依据 PERSONAL_CONTROL_CENTER_DEVELOPMENT.md 对现有实现做证据驱动验收。这一轮是检查，不自动改代码或系统。

先读取项目约定、源码、依赖和已有测试结果，运行非破坏性的构建与假服务测试。重点检查：
1. 是否真实 WPF、普通权限、单实例；隐藏/退出/Explorer 恢复路径是否完整。
2. 是否存在假状态、写入未回读、迟到查询覆盖新值、拖动时向错误设备写入等问题。
3. 原生 COM/句柄/回调是否正确释放，唤醒是否同线程清除，隐藏是否仍高频运行。
4. 配置损坏/高版本/导入入口能否安全处理；命令启动是否拼接 shell；日志是否泄露个人信息。
5. API 不支持、角色部分成功、网络错误、快捷键冲突的降级是否真实可用。
6. 性能与 DPI/动效结论是否有实测证据，mock 是否可能被误当正式模式。

发现项提供严重度、准确文件与行号、触发条件、用户影响、证据和建议修复；推测注明待验证，不凑数。不实际改变宿主系统，不主动重启 Explorer，不安装新组件。

最后给出“可验收/有条件候选/不可验收”的结论、发布阻断项，以及最短的人工验证清单。没有证据通过的用例写未验证，不把构建成功当成整体验收通过。
```

## 5. 批准一项真机测试的模板

只在开发者已经解释具体测试时发送，填好括号，不要原样发送占位内容。

```text
我批准本次仅执行以下真机测试：［测试编号、具体操作、目标设备/方案、持续时间］。
先记录相关原值，测试后仅当当前值仍等于测试设置值时恢复；检测到外部修改就停止自动恢复并告知我。不得修改其他系统参数、重启电脑、安装驱动或扩展测试范围。
如果恢复本身失败，明确报告实际残留状态与手动恢复方法，不重复无限重试。更新测试记录。
```

## 推荐顺序

想先看手感：仅做 M0–M1 → 人工体验 → 继续开发（明确批准进入 M2–M5）→ 独立验收。

想直接做完：主提示词 → 必要时逐项批准真机测试 → 独立验收。

主提示词要求自主推进的是安全的开发工作，不是对宿主机器的无限权限。文档里所有性能数字都是验收目标，不能仅靠提示词承诺实现。
