# 0.9.1 操作连续性

| Before | After | Why |
| --- | --- | --- |
| 开合 6 DIP、140/120 ms | 内容 4 DIP、打开 140 ms、关闭 90 ms，反向按剩余透明度缩短时间 | 保持轻快并从当前进度继续 |
| 刷新反复重建音频、电源、亮度列表 | 值不变时复用集合和控件；能力变化只改卡片可见性 | 保留选择、焦点和未提交亮度草稿 |
| 展开设备列表时滚动条挤压宽度，自动焦点可能滚动 | 主滚动区固定预留宽度；展开不强制移动焦点 | 触发按钮的位置稳定 |
| 输出切换没有局部等待确认流程 | 原设备继续显示，等待反馈；确认目标后收起；失败保留列表 | 不提前显示成功 |
| 状态提示改变卡片/页脚高度 | 音频、电源和输出预留一行，底部固定一行，完整文字见提示框 | 不推走鼠标落点 |
| 电源仅有勾选文字 | 确认后的当前方案显示选中背景，等待期间禁止重复提交 | 避免乐观选择回跳 |

音量数字列固定 40 DIP 并采用等宽数字，拖动不添加缓动。主窗口背景直接显示，仅内部内容淡入位移，不缩放文字。配置关闭动画或系统关闭动画时仍立即显示/隐藏。

刷新整体失败或部分设备读取失败时保留已有读数，明确显示数据待确认，并暂停扩展设备写入直到读取恢复；不把旧读数称为当前确认状态。实际音频与电源仍通过协调器处理过期结果和验证。

可运行假服务验收 `UiAcceptance --allow-ui-continuity artifacts/evidence/CONTINUITY-0.9.1` 覆盖开合反向、音量跟手/数字宽度、展开触发位置、刷新不丢选择、设备切换等待/失败/确认收起、长错误不移动布局、外部窗口激活后关闭。截图和结果在该目录。新增单元测试覆盖集合稳定、刷新失败保留与恢复、电源等待及失败保留原选项。

仅使用假服务和演示窗口，不调整真实系统状态。没有真实设备切换写入实测，也不宣称已完成游戏期间或完整多屏/DPI 体验验收。此轮为本地候选，GitHub Release 仍为 0.9.0。

补充核验：替换动画前将当前透明度和位移写为基础值，避免新动画首帧恢复默认值。此机 125% 下使用 PrintWindow 捕获实际演示窗口（native.png），当前设备名称正常可见；离屏 RenderTargetBitmap 对截断文本有漏绘，不以离屏截图单独判定实际窗口缺字。
